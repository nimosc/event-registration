# אומן שהוא גם ODT ("גם וגם") — מפרט

**תאריך:** 2026-09-24
**סטטוס:** טיוטה לאישור

## הבעיה

עמודת "תפקיד במערכת" (`color_mm18btbr`) בלוח האומנים מאפשרת ערך אחד: `אומן` או
`ODT`. הרבה אנשים בעמותה הם שניהם. היום כזה אדם מוגדר כאחד מהם, ולכן:
- רואה רק הזמנות מסוג אחד (אומן → הזמנות שצריכות אומנים; ODT → שצריכות ODT).
- כל הרשמה שלו נספרת למכסה של אותו סוג בלבד, גם כשההזמנה צריכה דווקא את השני.

## ההחלטות שהתקבלו

1. תווית חדשה **אחת** בעמודה: `אומן+ODT`.
2. **"מנהל אומן" נשאר מנהל + אומן.** אין "מנהל ODT" ואין "מנהל אומן+ODT".
3. בהזמנה שצריכה גם אומנים וגם ODT — **האומן בוחר** באיזה תפקיד הוא מגיש.
   בהזמנה שצריכה סוג אחד בלבד — התפקיד נקבע אוטומטית, כפתור אחד כמו היום.

לא בסקופ: שינוי במבנה ה-subitems (הם כבר נושאים תפקיד לכל הרשמה); שינוי
בדוחות מעבר למיפוי התווית החדשה.

## מודל

```ts
// src/lib/roles.ts
export type Role = "אומן" | "ODT" | "אומן+ODT" | "מנהל" | "מנהל אומן";
export type RegistrationRole = "אומן" | "ODT";

/** התפקידים שבהם המשתמש יכול להירשם. ריק = מנהל טהור. */
export function getRegistrationRoles(role: Role): RegistrationRole[];
//  אומן, מנהל אומן → ["אומן"]   ODT → ["ODT"]   אומן+ODT → ["אומן","ODT"]   מנהל → []
```

`getRegistrationRole` (יחיד) נמחק. כל הקוד שגידר על `!== null` עובר ל-
`getRegistrationRoles(role).length > 0`. `isAdmin` ללא שינוי.

## זרימה

### `/api/orders` — מה המשתמש רואה
- `userRoles = getRegistrationRoles(session.role)`.
- הזמנה מוצגת אם **לפחות אחד** מתפקידי המשתמש נדרש בה (`requiredCount > 0`
  לאומן, `odtRequired > 0` ל-ODT).
- לכל הזמנה מחושב `roleOptions` — רק החיתוך של תפקידי המשתמש עם מה שההזמנה
  צריכה:
  ```ts
  roleOptions: Array<{
    role: RegistrationRole;
    label: "אומנים" | "ODT";
    required: number; applied: number; approved: number;
    isFull: boolean; isOpen: boolean; spotsRemaining: number;
  }>;
  ```
- השדות היחידניים הקיימים (`roleLabel`, `roleCapacityCeiling`, `roleApplied`,
  `roleApproved`, `isRoleOpen`, `isRoleFull`, `spotsRemaining`) ממשיכים להתמלא
  מה-option הראשון — כדי שהמסכים הקיימים לא יישברו. `canRegister` = יש option
  פתוח ו-ההזמנה פתוחה.
- `isRegistered`/`subitemId`/`candidacyStatus` כמו היום (לפי ה-subitem של
  המשתמש). ה-subitem כבר יודע באיזה תפקיד נרשם (`artistType`) — מוחזר כ-
  `registeredAs: RegistrationRole | undefined`.

### `/api/register` POST — ההרשמה
- גוף: `{ orderId, role?: "אומן" | "ODT" }`.
- `userRoles` ריק → 403 (כמו היום).
- `role` חסר: אם למשתמש תפקיד אחד → הוא. אם שניים → נגזר מההזמנה: אם היא
  צריכה רק אחד מהם → הוא; אם שניהם → 400 `"יש לבחור תפקיד להרשמה"`.
- `role` נתון: חייב להיות בתפקידי המשתמש **וגם** נדרש בהזמנה, אחרת 400.
- `createSubitem(orderId, name, id, role === "ODT" ? "ODT" : undefined)` — כמו
  היום, רק שהתפקיד מגיע מהבחירה ולא מהמשתמש.
- כפילות: משתמש רשום כבר להזמנה (בכל תפקיד) → 400 כמו היום. אדם לא יכול
  להיות רשום פעמיים לאותה הזמנה בשני תפקידים.

### `OrderCard` — הבחירה
- `roleOptions.length === 1` → כפתור אחד "הגש מועמדות" (ללא שינוי נראה).
- `roleOptions.length === 2` → שני כפתורים זה לצד זה: "הגש כאומן" / "הגש כ-ODT",
  כל אחד עם מצב משלו (מלא / פתוח / מקומות). כפתור של option מלא מציג
  "רשימת המתנה" כמו היום לאותו מצב.
- אחרי הרשמה: כפתור ביטול אחד + שורה "נרשמת כ-ODT" / "נרשמת כאומן".
- שורות הקיבולת: שורה לכל option (היום שורה אחת).
- `onRegister(orderId, role)` — חתימה חדשה; `OrdersClient.handleRegister` מעביר
  את `role` ל-API ומעדכן את המונים המקומיים לפי התפקיד שנבחר (במקום
  `isOdt` מהמשתמש).

### שיבוץ ידני (אדמין)
- `/api/admin/assign` מקבל `role?: RegistrationRole`. חסר → נגזר מתפקידי
  האומן והצורך בהזמנה באותה לוגיקה של `/api/register`; דו-משמעי → 400.
- `/api/admin/assignable-artists` מחזיר לכל אומן `registrationRoles`.
- מודל השיבוץ: כשהאומן שנבחר הוא `אומן+ODT` **וגם** ההזמנה צריכה את שניהם —
  מופיע מתג "כאומן / כ-ODT" לפני "שבץ". אחרת אין שינוי.
- זה גם מתקן פער קיים: היום השיבוץ הידני תמיד כותב "אומן", גם ל-ODT.

### מיפויים נוספים
- `proxy.ts`, `page.tsx` של orders / my-registrations / invoices, NavBar:
  `getRegistrationRoles(...).length > 0` במקום `!== null`.
- `buildArtistTypeMaps` (דוח מדריכים, `monday.ts:~1230`): התווית `אומן+ODT`
  ממופה ל-`"אומן"` כ-fallback — משמש רק ל-subitems ישנים בלי עמודת תפקיד. כל
  הרשמה חדשה נושאת תפקיד מפורש, אז זה לא משפיע קדימה.
- `NavBar`: הבאדג' מציג `אומן+ODT` כמו שהוא.
